# Design canvas

The design canvas is the source of truth for stockpot's interface: the kit and every screen at 390,
768 and 1440 px, in light and dark. The canvas itself lives in the owner's design tool; this folder
is its export, so that every board can be read, reviewed and implemented from the repository.

## Change the canvas first, then the code

When the code and a board disagree, the board wins. To change the design:

1. Change the canvas in the design tool.
2. Export it again into this folder (see [Exporting again](#exporting-again)).
3. Change the code to match, in a story that names the boards it implements.

Never fix the design here or in the code alone: the next export would undo it. Every UI story names
its boards in a **Boards** line, and its pull request is reviewed against them; the
[styling guideline](../guidelines/styling.md#start-from-the-design-canvas) has the rule for the code.

## What is here

| Path                     | What it is                                                                                                                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`kit.css`](kit.css)     | Every kit token as CSS custom properties, for light (`:root`, `[data-scheme='light']`) and dark (`[data-scheme='dark']`). WEB-1 moves them into `packages/ui/src/theme.css`.                         |
| [`boards/`](boards/)     | One image per board and scheme, rendered from the canvas: what to look at when implementing or reviewing.                                                                                            |
| [`project/`](project/)   | The canvas's own files, as the design tool stores them: the index `canvas.json`, one `.dc.html` file per board, and the CSS the boards read (`tokens.css`, `kit.css` for primitives, `screens.css`). |
| [`README.md`](README.md) | This file: how the canvas is organised and the list of boards.                                                                                                                                       |

The `.dc.html` files render only inside the design tool, which supplies their runtime; read them for
exact values, and the images for the look. Fonts are named by family only, Inter for the interface
and Literata for what the owner reads. The boards load them from Google Fonts to draw; production
serves them from the app, and no font files are committed.

## How the canvas is organised

The canvas has five pages, one per design story. Each board is a sheet with a header (a kicker such
as "stockpot kit · 01", a title and a paragraph on what the board decides) above its content.

- **Kit** (DES-1): nine sheets, 1680 px wide, for the foundations (colour, type, spacing, categories)
  and the primitives (controls, card, lists, navigation, feedback). Most draw a light panel and a
  dark panel side by side.
- **Capture**, **Notes and cards**, **Settings and first run** and **Today** (DES-2 to DES-5): one
  screen board per width. A screen board stacks a light panel over a dark panel; each panel is a row
  of numbered frames at the device width, one per state (`01 · Suggestions`, `02 · Typing`, …), with
  a line under the number on what the frame shows. Long pages are drawn at full scroll length.
  Frames with the on-screen keyboard show the room it leaves.

The app shell around a screen is a tab bar at 390, an 88 px side rail at 768, and a 264 px sidebar
with a reading column of at most 680 px at 1440. The screen boards add `project/screens.css`
(device frames, the shell and screen parts) on the kit tokens, with no new tokens.

## Decisions

The owner approved each page on 2026-11-18 (kit) and 2026-11-19 (screens). The full decisions are
in the last comments of [DES-1](https://github.com/MrStnr21/stockpot/issues/8),
[DES-2](https://github.com/MrStnr21/stockpot/issues/9),
[DES-3](https://github.com/MrStnr21/stockpot/issues/10),
[DES-4](https://github.com/MrStnr21/stockpot/issues/11) and
[DES-5](https://github.com/MrStnr21/stockpot/issues/12); in short:

- **Palette:** neutrals tinted toward pink (OKLCH hue 350), one accent, Rose (hue 355: #CB317F in
  light, #F589B6 in dark), and red (hue 27) only for destructive actions. Every text pair passes
  4.5:1 in both schemes. OKLCH in `kit.css` is the source; the hex on the boards is its sRGB
  rendering.
- **Type:** Inter for the interface (title-l 28/34 down to micro 11/14), Literata for card titles,
  card text and reports (read-display 34/40 down to read-quote 15/22 italic). Both are variable and
  cover Latin and Cyrillic.
- **Spacing, radius, elevation, motion:** Tailwind's 4 px step; radius xs 6, sm 10, md 14, lg 20,
  xl 28 and full; shadows in light, borders and depth in dark; fast 120 ms, base 200 ms, slow
  320 ms, shimmer 1400 ms, with standard, enter and exit easings. Reduced motion keeps colour
  changes and drops scale, slide and shimmer. Focus is a 2 px accent ring with a 2 px gap.
- **Categories:** six colours, each with solid (icon), soft (ground) and ink (text) values in both
  schemes, and an icon from one stroke set (24 px grid, 1.75 stroke). The icon and the name always
  come with the colour, so no category depends on hue alone.

  | Category   | Hue | Light solid | Dark solid | Icon                    |
  | ---------- | --- | ----------- | ---------- | ----------------------- |
  | English    | 255 | #2D74CA     | #75AEF5    | speech bubble with an A |
  | AI         | 300 | #814EC6     | #B995F6    | sparkles                |
  | Technology | 195 | #008C8C     | #57C5C5    | code brackets           |
  | Concept    | 145 | #419547     | #77CB7B    | shapes                  |
  | Idea       | 65  | #C5770F     | #F3B94C    | lightbulb               |
  | Other      | 265 | #6D7584     | #9DA5B5    | circle with three dots  |

- **State** is drawn with `data-state` and ARIA attributes (pressed, disabled, `aria-busy` for
  loading), as the styling guideline asks, and token names follow Tailwind 4 theme variables.

## Exporting again

After the canvas changes, in the same pull request:

1. Replace `project/` with the design tool's project files, unchanged. Prettier skips the folder, so
   a re-export stays a plain copy.
2. Copy the token blocks of `project/tokens.css` into `kit.css`, keeping its header.
3. Render the changed boards to `boards/` with the same names: each board at its frame size in the
   design tool's runtime, headless, at 1x, cut as described under [Boards](#boards), saved as lossy
   WebP at quality 0.75. Add a row here for a new board, and remove the images of a deleted one.
4. Read the changed boards for personal data before committing. Sample notes stay generic: no real
   names, emails, machine or network names, and none of the owner's own notes.
5. Update the **Boards** line of every UI story the change touches.
